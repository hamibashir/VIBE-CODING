## 3. Implementation Approach

```
+------------------------------------------------------------------------+
| Client: POST /api/v1/upload (multipart/form-data: images=[file1, ...])|
+------------------------------------------------------------------------+
                                    |
                                    v
                   +----------------------------------+
                   |  1. authenticateUser Middleware  |
                   +----------------------------------+
                     /                              \
          No/Invalid JWT                         Valid JWT
                   /                                  \
                  v                                    v
          401 UNAUTHORIZED               +---------------------------+
                                         | 2. uploadImages Middleware |
                                         +---------------------------+
                                           /                       \
                                   Validation Error              Valid
                                         /                           \
                                        v                             v
                                  400 Bad Request          +----------------------+
                                                           | 3. uploadController  |
                                                           +----------------------+
                                                                      |
                                                                      v
                                                           +----------------------+
                                                           | 4. storageService    |
                                                           |    uploadFile()      |
                                                           +----------------------+
                                                                      |
                                                                      v
                                                           +----------------------+
                                                           | 5. 201 Created       |
                                                           |    { urls, images }  |
                                                           +----------------------+
```

1. **Create Controller (`uploadController.ts`):**
   - Check if `req.files` is empty or missing $\rightarrow$ `sendError(res, 'NO_FILES_PROVIDED', 'Please provide at least one image to upload', undefined, 400)`.
   - Map each file buffer to `uploadFile(file.buffer, file.originalname, file.mimetype)`.
   - Wrap in `try/catch` with automated rollback: if an error occurs mid-batch, delete any files already saved to disk/cloud in that batch to prevent orphaned storage.
   - Return `sendSuccess(res, { urls, images }, 'Images uploaded successfully', 201)`.
2. **Create Routes (`uploadRoutes.ts`):**
   - Route `POST /` $\rightarrow$ `[authenticateUser, uploadImages, uploadImagesHandler]`.
   - Route `POST /single` $\rightarrow$ `[authenticateUser, uploadSingleImage, uploadSingleImageHandler]`.
3. **Mount in `server/src/index.ts`:**
   - `import uploadRoutes from './routes/uploadRoutes';`
   - `app.use('/api/v1/upload', uploadRoutes);`

## 5. Important Business Logic & Edge Cases
- **Authentication Required:** Anonymous callers receive `401 Unauthorized` (`TOKEN_MISSING` / `INVALID_TOKEN`), protecting platform storage from unauthenticated scrapers and bots.
- **Empty File Payload:** Request with valid token but empty `images` array receives `400 Bad Request` (`NO_FILES_PROVIDED`).
- **Batch Atomicity & Cleanup:** If one image fails storage processing, any previously stored images in the current batch are automatically removed using `deleteFile(publicId)` before returning an error response.
- **Full Metadata Return:** Returns both `urls: string[]` (for straightforward frontend form binding) and `images: StorageResult[]` (preserving `publicId` and `driver` for ad moderation and CDN tracking).
- **Static URL Accessibility:** In local development, returned URLs (e.g. `/uploads/abc.png`) are immediately servable and fetchable via `GET http://localhost:5000/uploads/abc.png` (configured in Task 4.2).
